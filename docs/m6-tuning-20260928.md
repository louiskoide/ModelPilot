## Findings and limitations

The run used project-local Claude Code 2.1.278. Opus requests received HTTP 400
with `claude_code_version_too_old`: the provider required 2.1.280 or newer.
The reported Opus 0/16 is a client compatibility failure, not a model quality
result. Comparisons involving that arm are invalid.

Jev made one routing decision per task and selected Sonnet 5.5 for all 16 tasks.
ModelPilot passed all 16 tasks with no recorded escalations, so this run does
not validate its escalation behavior. These are tuning results, not a held-out
comparison or a general savings claim.

## Repair already implemented

Live runs automatically remove write permissions from the managed benchmark
venv's site-packages, then verify the lock before requesting provider credentials.
The lock does not follow symlinks or modify a global Python environment. It
still stops the run if dependencies remain writable. This replaces the repeated
manual chmod step; it is not an OS security sandbox.

Validation: 24 tests passed across `tests.test_bench_tasks` and
`tests.test_bench.PreflightTests`, including three new environment-lock tests.
All 16 task references also passed the earlier free preflight after restoring
the ignored parse checkout and pinned Python environment locally.

## Analysis on the pinned checkout (September 28, $0)

This run can't be used for comparisons or tuning. Besides the Opus arm, the client version and the code version shaped the other arms' results:

- **Code:** it ran from `main` at `173f21a`, which had PR #5 but not #6. The ModelPilot arm was the stuck ladder starting on Sonnet 5.5 medium, not the Jev-advised design (Jev predicts, ModelPilot's cost gate decides whether to jump) that PR #7 brings to `main`. With no Sonnet 5.5 thinking-history evidence on that commit, its rungs would also have been deferred.
- **Client 2.1.278 doesn't know Sonnet 5.5.** Checked against the owned fixture with 2.1.278 installed in scratch space and no `--effort`:
  - it sends Sonnet 5.5, Opus 5.5 and the Jev placeholder **high** effort (ModelPilot's client asks for medium);
  - its first main-loop request is **50.0 KB** for Sonnet 5.5 and Haiku but **17.7 KB** for Opus 5.5 and the Jev placeholder, all with `max_tokens` 32,000.

  On the pinned 2.1.284, Sonnet 5.5, Opus 5.5 and the placeholder all get about 17.8 KB, and Sonnet 5.5 and Opus 5.5 default to medium.
- **So the cost ordering mostly reflects the client:**
  - Jev ($0.084) carried requests about three times smaller than fixed Sonnet 5.5 and ModelPilot.
  - ModelPilot ($0.108) ran at medium effort where fixed Sonnet 5.5 ($0.122) ran at high.
  - Neither difference exists on the pinned client.
- **What still holds:**
  - Sonnet 5.5 passed all 16 tuning tasks, at medium (ModelPilot) and at high (fixed); Haiku passed 14.
  - Jev's router chose Sonnet 5.5 for all 16.

  On this task set, a Jev-advised ModelPilot would therefore rarely have reason to move to Opus. Its measurable differences would come from effort, prompt overhead, context tools and stuck evidence, not from putting hard tasks on a stronger model.
