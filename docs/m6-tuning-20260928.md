## Findings and limitations

The run used project-local Claude Code 2.1.278. Opus requests received HTTP 400
with `claude_code_version_too_old`: the provider required 2.1.280 or newer.
The reported Opus 0/16 is a client compatibility failure, not a model quality
result. Comparisons involving that arm are invalid.

Jev made one routing decision per task and selected Sonnet 5.5 for all 16 tasks.
ModelPilot passed all 16 tasks with no recorded escalations, so this run does
not validate its escalation behavior. These are tuning results, not a held-out
comparison or a general savings claim.

## Repair already implemented

Live runs automatically remove write permissions from the managed benchmark
venv's site-packages, then verify the lock before requesting provider credentials.
The lock does not follow symlinks or modify a global Python environment. It
still stops the run if dependencies remain writable. This replaces the repeated
manual chmod step; it is not an OS security sandbox.

Validation: 24 tests passed across `tests.test_bench_tasks` and
`tests.test_bench.PreflightTests`, including three new environment-lock tests.
All 16 task references also passed the earlier free preflight after restoring
the ignored parse checkout and pinned Python environment locally.
