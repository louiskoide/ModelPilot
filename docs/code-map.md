## Code map

- `cache_probe.py`: cache experiments, authenticated HTTPS transport, safe errors, usage pricing. Optional certifi supplements TLS roots; verification must remain enabled. `tier` (October 8): a model priced by prompt length (Haiku 5.5) has `tiers` and no flat rates; `cost` picks a request's tier from its usage (`prompt_tokens`), pre-send estimates take the dearest, and `switch_policy._rate` refuses one. `switch_policy` (October 8): `measured_candidates` weighs settings with measured outcomes beside Jev's pick at turn starts (rows `measured_only`; a measured downgrade skips Jev's confidence check), `candidate_efforts` limits a candidate model to its measured efforts, `_segments` prices a forecast request by request at a price-by-length model's tiers, and `_check_models` (load and arm overrides) refuses a candidate without per-message effort while it's on. `bounded_by` (October 9): a measured setting's outcomes stand for a stronger setting's in `measured_ok` and `floor_allows` only on the same model or when its model's `outcomes_count_for_stronger` is true (Haiku 5.5's is false). `thinking_probe --suite haiku-5-5` has the proxy move's effort cases (`HAIKU_EFFORT_CASES`); `--suite haiku-effort` (October 9) adds native references and an xhigh pair (`HAIKU_EFFORT_CHECK_CASES`), decided by `move_effort_verdict`, a rule fixed before its run. `dated` (October 8): a model whose prices changed (Sonnet 5.5's cache reads, October 7) lists them by start time; recorded rows are priced on their own day (`started_unix`), live requests and forecasts on today's. `bench_report --price-at DATE` prices every row on one day's prices (`on_date`, `repriced`).
- `proxy.py`, `fixtures.py`, `soak.py`: streaming pass-through proxy and local synthetic checks; its dry-run `forecast` compares only `SWITCH_TARGETS` (Sonnet 5.5, Opus 5.5). Proxy requests identity encoding to keep usage parsing reliable. No active routing. `ProxyServer(system_marker=)` logs per Messages row only whether the system prompt contained that text (`system_marker`). Accepts strict chunked uploads, passes through `GET /v1/models` only, and labels rows `kind`/`path`/`tool_count`. Token counting (`/v1/messages/count_tokens`, free) is logged as `kind: count_tokens` at $0; a Messages reply without usable usage records `usage_problem`. With `--governor-*` flags, each billable request is reserved (never enforced) and settled under an `mp-` ID shared by the log row and the governor. The fixture has a scripted tool-use mode (`server.script`) for driving a real client offline. `ProxyServer(catalog=)` filters `/v1/models` to a model-constrained arm's set. Since October 14 (cloud batch) header repeats are kept in order (`clean_headers` returns pairs, `send_request` sends them), only a failed write to the client counts as the client going away (`ClientGone`; an upstream close or reset is a `transport_error`, with a 502 if nothing was sent), and a reply whose `server_tool_use` counts a web search is unpriced (`cache_probe.server_tool_fees_unknown`). Since October 18 every Messages, token-counting and side-call row logs the reply's `anthropic-ratelimit-*` headers (`rate_limit`, `rate_limit_headers`). The names are kept less that prefix, and the values as sent if they are short plain tokens, else None. On a subscription these are the usage-limit readings. The fixture can add reply headers (`server.response_headers`).
- `jev_accounted_launch.mjs`: harness launcher that puts ModelPilot's proxy behind Jev's for wire accounting. Its differences from the stock launcher are listed in its header; `--self-test` checks the plumbing without Claude Code; `--serve` runs only Jev's proxy for a bench trial (the harness starts Claude Code); `--stub-route` replaces TypeSafe in offline tests only.
- `m2.py`: transactional SQLite tasks, revisions, leases, corrections, observations, stuck ladder (heuristic-v3 since October 16: errors hashed by their normalized failure signature (`failure_signature`, `error_hash`, `normalize_error`); the agent's own test runs observed as `stalled_agent_tests` and `repeated_agent_failure`, never scored; `file_hashes`), output storage/paging. `m2_mcp.py`: read-only MCP expand_output/get_task/stuck_recommendation.
- `claude_check.py`: isolated Claude Code M1/M2 live harness, explicit tool-call/result validation and client/proxy reconciliation. Local client at `work/claude-client/node_modules/.bin/claude` if present: pinned 2.1.284 since September 28 (2.1.282 kept in `work/claude-client-2.1.282` for earlier runs).
- `workers.py`, `worker_check.py`: bounded search/fixed-command host adapters with one Sonnet summary per task; per-role histories, leases and accounting. Test subprocesses do not inherit provider credentials. This is not an OS sandbox.
- `m4.py`, `cascade_check.py`: dry-run verifier and shadow planner; two-request live draft check on Sonnet 5.5 (`--execute-fallback`: one governed Opus 5.5 fallback). Exact spans prove grounding, not relevance. Destructive operations excluded; edits escalate.
- `m5.py`: coalesces latest per-kind changes at idle (`idle_boundary`: 330 s for a 5m cache lifetime, 3,630 s for 1h or unknown)/expiry/justified-switch/explicit-boundary points; defers during in-flight work. `compaction_check` (October 13, corrected that night: `/compact` is one more request): whether a rebuild's compaction pays within a turn, on cost alone. Budget reserves before dispatch, settles actual cost, halts on unknown cost; caller integration required. Learning needs both draft/fallback outcomes and disjoint train/validation data; not a bandit.
- `governor.py`: durable integration surface (see `docs/governor.md`). Dry-run only; `mode` other than dry-run raises. `admit(gate='spent')` admits on measured spend below the limit (a client budget stop's rule), used by the active arm; the default gate needs the estimate to fit beside pending reservations. Expired pending reservations become orphaned (unknown cost, halt) until settled with measured evidence. `governed_transport` wraps a Worker transport with admit/settle. `execute_fallback` runs one opt-in, admitted fallback and re-verifies it. `reconcile_log` repairs settlement from a proxy log. `observe_setting` (October 4) acknowledges a rebuild plan once every change in it has been seen since planning: model and top-level effort from the proxy's successful main-loop rows, compaction from the `SessionStart` hook; a prune always needs `ack-rebase`. `plan_rebase` keeps a queued compaction only where `m5.compaction_check` says it pays, on the proxy's `observe_context` notes (October 13). Pricing rules are shared through `cache_probe.priced_usage`.
- `hooks.py`: Claude Code hook entry point plus coordinator CLI (`queue-change`, `ack-rebase`, `status`, and since October 14 `run-suite`). Always exits 0. Since October 16 it also observes the agent's Bash test runs (`agent_test_run`, through `delegation`'s recognizer and parser), labelled as the agent's and never also an error, and the files a Bash call changed (`bash_file_evidence`, `changed_files`: git's list plus files already observed). Payload shapes are recorded in `tests/fixtures/hooks-2.1.280/`, and a passing and a failing Bash test run from 2.1.284 in `tests/fixtures/hooks-2.1.284-bash/` (2.1.284 sends the same fields, checked October 4: no model anywhere, `effort.level` on PreToolUse/PostToolUse/Stop). A correction pending at `Stop` blocks the stop once per revision with the delivery as the reason (2.1.284 shows the model the reason twice, once as a "Stop hook blocking error" with the hook's command line). With `MODELPILOT_REVIEW_AT_STOP=1` (October 5, the delegation arm's review at the finish) `Stop` otherwise holds the agent's finish once per turn (`review_block`: task in progress and acknowledged, channel declared, measured spend below the limit), so the policy can review on the request that continues the turn. `governed_session.py`: one isolated governed Claude Code session with a mid-flight correction (`--live` is billable); `--scenario turn-end-rebuild` (October 12, plan item 12) runs one session as four invocations for live evidence of turn-end delivery and a rebuild plan acknowledged by observation (`run_rebuild_session`, `rebuild_status`).
- `own_sessions.py` (October 17; paid behind `--live`, since it starts a client): the user's own Claude Code session through the dry-run proxy on a free loopback port, with every model's rates (`bench.rates`) and the dry-run governor's ledger shared by every session (`runs/own-sessions/ledger.sqlite3`). Only `ANTHROPIC_BASE_URL` is set in the client's environment; the user's settings, login and terminal are otherwise as they are, and no global configuration is touched. Ctrl-C belongs to the client. Per session, `runs/own-sessions/<stamp>-<pid>/`: the proxy's rows and `summary.json` (requests, known and unknown cost, models, and the main-loop gaps against each request's lifetime boundary, `m5.idle_boundary`). The real-work measurement for idle plans and delegation (`docs/governor.md`, "Own sessions"). `--keep` (October 18) adds the cache keeper and `summary.json`'s `keeper` section. `summary.json`'s `rate_limit` (October 18, `rate_limits`) reports the usage-limit headers: replies, statuses, and per window (5h, 7d, 7d_oi) the first and last utilization, resets and the smallest step.
- `transcript_replay.py` (October 17, $0): the cache keeper's pre-registered test (`docs/governor.md`, "Cache keeper: transcript replay"). Reads the client's own transcripts (`~/.claude/projects`: per response its model, ID, usage and timestamps, never message text), one request per response, and prices what a keeper pinging every 55 minutes would have saved and spent at 12 settings, against the month's API-rate total; the precondition (warm starts past an hour) gates the decision.
- `keeper.py` (October 18; sends requests only inside `own_sessions --live --keep`): the cache keeper (`docs/cache-keeper-design.md`). A `Keeper` per `ProxyServer(keeper=)`, which needs a dry-run governor and no policy. It holds the last answered main-loop request whose breakpoints are all 1h, in memory with its headers, and 55 minutes after the entry was last read re-sends it at max_tokens 1, not streamed, through `side_call` (`kind: keeper_ping`, IDs `mp-keep-…`).
  - **Stops**, until the next main-loop request: 4 hours after the request (`window_end`), the client's exit, a timer found more than 58 minutes after the last read (`late`), or $3 of pings that day across the shared ledger (`daily_cap`).
  - **Disables** for the process: a non-200, an unknown cost, a refusal, or a read under 95% (`ping_missed`).
  - **Holds off idle sleep** with `caffeinate -i -w <pid>` while a request is held, and checks the wall clock every 30 s.
  - `keeper.summary` reports pings against the rewrites kept returns avoided. Stops are logged as `kind: keeper`.
  - `ProxyServer.side_call` takes `kind`, `mode` and `id_prefix` for it, and `timeline` counts pings as billed.
- `keeper_ping.py` (October 17; paid behind `--live`, about $0.10): what a cache keeper's ping costs. Direct API, Opus 5.5 at xhigh with adaptive thinking, a nonce-led ~8,000-token system prefix cached 1h: a seed, the same body at max_tokens 1, 16, 64 and 256 until one is accepted (a 400 climbs, any other error stops), then the seed's body again; `--renewal` waits 55 minutes before the ping and before `again`. Reports the ping's tokens and dollars and reprices the replay's best setting with them.
- `suite_adapter.py` (October 14, cloud batch, offline; off by default): the governor's test adapter. A declared suite (`MODELPILOT_SUITE` or `hooks run-suite --spec`), run by the host without a shell or credentials, read from JUnit XML or its exit status (`pass`/`fail`/`unknown`, never a pass by default), and landed as an M2 observation (`suite`, `suite_outcome`, `failures`, `tree_hash`) only if the watched files still hash as at the start and M2 accepts the revision; the `Stop` hook runs it at a turn's end. See `docs/governor.md`, "Test adapter".
- `bench_tools.py`: the ModelPilot arm's stdio MCP tools (`run_tests`, `search`, `expand_output`), given only while delegation is on (`bench.arm_tools`); host operations only, excerpt plus handle above the threshold. `fixture_dispatch.py`: the dispatch core (`Dispatcher`: fence, reserve, settle, confirm) plus the fixture-only `FixtureDispatcher` and `ProxyPolicy` (ladder escalations in the proxy, owned fixture upstream only). `active_policy.py`: `ActivePolicy`, the ModelPilot benchmark arm's live policy (user-approved for that arm only). At each turn start, on stuck evidence and at mid-task steps (the host-run suite flipping between failing and passing, or spend reaching the last decision's forecast; since September 29, offline only) it asks Jev for a model and effort (`advisor.py` + `jev_advisor.mjs`: the unchanged compat checkout's own prompt extraction, model descriptions and model question, plus one effort question; TypeSafe key only, failure means stay). It then jumps straight to a setting when `switch_policy.py` says the expected total cost (switch + P_ok × run + (1 − P_ok) × recovery) beats staying, with hysteresis and conservative downgrades. There's no ladder, and a stuck task with nothing stronger stops. R6 admission is on measured spend, with refusals answered by the proxy (HTTP 400, `kind: refused` rows, never forwarded). With `per_message_effort.enabled` (on since October 1; new messages only at turn starts, `effort_changes_at`) the proxy keeps the client's top-level effort and carries the setting's effort in effort-only system messages, each put back where it was first sent, so an effort change keeps the cache (`carry_effort`; rows record `effective_effort`). Since October 3 (offline): P_ok at turn starts and steps blends the tuning split's measured pass rates with Jev (`calibration`, `jev_weight` fitted, 0.03 since October 6; stuck evidence stays uncalibrated), a failure is redone on a stronger model at the turn's effort and then in a new turn, and `run_cost` uses the measured task shape with cache writes, effort and model factors for requests and output, and `bytes_per_token` 2.8 (see `docs/m6-modelpilot-policy.md`, "Calibration and the measured cost model"). `policy_replay.py` ($0) replays the decisions journaled in each trial's governor database through the current policy; with `--arm`, through that arm's overrides and from its start (S0). `--intervals` (October 15, a report, off by default) adds 95% intervals on the measured pass rates and, for each decision, what within them would change it. `configs/modelpilot-policy.json` holds the models, efforts, cache-switch behaviour, step settings, per-message effort, calibration, `return_reuse` (warm-return pricing, on since September 30 for returns at most `max_positions` = 25 content positions after the setting was last sent, counted by `switch_policy.content_positions`) and cost-model guesses; `policy_actions.MODELS` reads it. `bench.arm_adapter` builds the arm with the R5 tools, and a `JevAdvisor` when the arm names Jev and the TypeSafe key is given; since October 11 no shipped arm does: without an advisor, turn starts weigh the measured settings alone and stuck evidence moves to `stuck_escalation` (Opus 5.5) (`switch_policy._unadvised`; `docs/m6-modelpilot-policy.md`, "No advisor").
- `loopback_fixture.py`: `LoopbackFixture`, an owned loopback HTTP upstream (JSON, stream, truncated, error and cancelled scenarios) answering through `fixture_dispatch.StrictFixture`; no externally supplied endpoint or credentials. Used by `fixture_dispatch` and `tests/test_loopback_dispatch.py`. Listed October 15 (overnight hygiene check).
- `delegation.py` (October 5, offline): consults and handoff notes for the ModelPilot arm (`docs/m6-modelpilot-policy.md`, "Delegation"). Builds the consult brief from host facts only (ledger instruction, latest `run_tests` result via its stored handle, diff against the trial's base commit, why it asks), the consult and handoff-note request bodies, and deliveries kept in place: one more text block on Claude Code's trailing system note (or a new system message after a user message), put back on the same message in every later request, so the cache and thinking survive. `ActivePolicy.consult`/`handoff_note` send them through `ProxyServer.side_call` (admitted on measured spend, settled, logged `kind: side_call`; `bench.accounting` adds `side_calls`/`side_cost_usd` and keeps them out of the client token match). `switch_policy` prices a consult candidate (P_consult = P_ok(current) + `effectiveness` × the gain) and a note's cost on mid-task model moves; config `delegation` is off in `modelpilot`, and the `modelpilot-delegate` arm turns it on through `bench.ARMS[...]['policy_overrides']` (`switch_policy.with_overrides`), with `consult.force: ['agent_finish']` (October 5; was `tests_pass`): `ActivePolicy.finish_review` makes the first main-loop request after a held finish (`review_block`, journaled by the hook) a forced step, and the adapter sets the hook's flag from `active_policy.reviews_at_finish`; trials record `held_finishes`. `policy_replay --arm` replays through an arm's overrides.
- `bench_tasks.py`: mines SWE-bench-style tasks from cloned repos (ignored `work/bench/repos/`), history-free checkouts, hidden grader (test dir restored to the reference commit, run without credentials, fresh HOME/TMPDIR, skips never count as run), validation (`python3 -m modelpilot.bench_tasks validate`). Task specs are in `bench/tasks/`. `bench.py`: task × arm × trial harness with isolation, identical limits, wire accounting and grading. It adds a $0 reference preflight (a trial must pass as many hidden tests as its reference), a `single` or `followup` shape (`--resume` after `--gap`, other trials run during the gap), a pinned client binary, session stop reasons, leftover-process cleanup, and crash-safe records. Fixed and Jev arms run; the ModelPilot arm runs only through `modelpilot_adapter.ModelPilotAdapter` (`adapter=`, dry-run, never benchmark-eligible); `--live` is billable and requires `--run-budget` (and a TypeSafe key at a hidden prompt for Jev arms). One ModelPilot proxy serves a whole trial; `ProxyServer.wait_idle` makes sure every accepted request is logged at session end and close. `bench_jev.py`: per-trial Jev router (`jev_accounted_launch.mjs --serve`, Jev's proxy alive across a follow-up so its routing state carries), checkout verification before every session, key separation (router never gets the Anthropic key, client never the TypeSafe key), per-trial `routing` record, `jev_router_unavailable` run stop on a TypeSafe auth failure. `prefetch_catalog` feeds Jev a (filtered) catalog for model-constrained arms such as `jev-compat-o55`. Jev dollars are provider cost only (`cost_scope`, router unpriced, a lower bound). Rejected requests keep the headline cost unknown; `…_if_rejected_free_usd` is a labeled sensitivity figure. `bench_report.py`: cold-equivalent cost (cache reads inherited from earlier trials repriced as writes; measured cost alongside) and a paired task-level bootstrap; `python3 -m modelpilot.bench_report <run>` rebuilds a summary; `--router-rates FILE` (October 14) prices Jev's TypeSafe decisions from an explicit rate with its source and date (`load_router_rate`, `router_cost`; scope `provider_plus_router_at_config_rate`); without it router cost stays unpriced, never $0; given several runs (October 3) it pairs their arms by task, labels an arm found in more than one run `arm@<run>`, and lists each run's code, client and auth. A fixed arm with `effort` (October 3: `sonnet-5.5-low`) passes `--effort`; its trials record `effort_check` and `bench_report` excludes one whose requests didn't carry it (`effort_not_applied`). A fixed arm with `append_system_prompt` (October 3: `sonnet-5.5-concise` and, with effort low, `sonnet-5.5-low-concise`; `bench/prompts/concise.md`) passes `--append-system-prompt-file`; its trials record the file's sha256 and `prompt_check` (the proxy's `system_marker` on every main-loop request), and `bench_report` excludes a miss as `prompt_not_applied`. Every trial records `write_sources` (`bench_report.write_sources`: cache writes split into cold_start, switch, growth, rebuild_expired, rebuild_changed and side, tokens and dollars), totalled per arm in the report. `--subscription-arms` (September 30) runs fixed arms on a `claude setup-token` subscription token (hidden prompt) instead of the API key; the subscription client asks for 1h cache writes, so those trials' dollars are API-key equivalent (1h writes repriced at 5m, `bench_report.api_key_equivalent`), as-sent kept, and they don't count toward `--run-budget`. A 429 ends a session as `rate_limited` (trial excluded, run stops). Since October 4 (user decision) a trial passes only if it also passes its task's edge suite, where it has one: `bench` runs it after the hidden grader (`edge`, `grade.edge_passed`, `pass_rule`), its reference check stops a run whose suite the upstream fix doesn't pass in full, and the manifest records `pass_rule` and each suite's SHA-256; `bench_report` takes older runs' edge results from their latest re-grade (`edge_missing` if none) and reports `hidden_passes` and `pass_rules` beside `passes`. `regrade.py` ($0): re-applies each trial's saved `agent.diff` to a fresh base checkout, re-runs the hidden grader, runs the frozen edge-case tests in `bench/edge_tests/<task>/` (tuning split, and the final split since October 18; a suite counts only if the reference fix passes all of it; rules in its README) and measures fix scope; output in a new `runs/regrade-…` directory. Since September 29 a trial's `agent.diff` and test-config check compare against the base commit the harness created, not `HEAD` (an agent that commits its fix left an empty diff), and trials record `agent_moved_head`.
