## October 7, 2026: plan item 7, the late-fix harness (offline; live step proposed)

$0, offline. What does a miss cost to fix once someone notices it late? `modelpilot/late_fix.py` ships each strict failure on record and has a fresh session fix it from a bug report the host writes. Harness built and the reports prepared; the live step hasn't run. Details: `docs/m6-benchmark-plan.md`, "Late fix, plan item 7's measured part".

- **The miss ships.** Each strict failure on record by the policy's models (`spec_tests.saved_fixes`; 29: parse 8, tomli 17, ISMAGS 4) is applied to its task's base workspace and committed, with the task's instruction as the commit message. Claude Code's git status context shows that subject line from the first request.
- **The host writes the report.** `prepare` ($0) re-grades each shipped miss with the test output kept and reports its first failing test (hidden tests, then the edge suite, then the repository's suite). The report has the reporter's test with the module-level definitions it uses, transitively, from the test file that ran (not in the agent's checkout), and the test runner's own account of the failure with paths made relative. No model writes it. It names one symptom, as a user would: ISMAGS's misses fail 20–28 hidden tests each and the report names one, so a strict repair has to fix the cause.
- **The repair is graded like a trial.** `run` starts one `bench.Trial` per miss (`LateFixTrial`: same limits, isolation, accounting and pinned client, no retries) on a fixed arm, `sonnet-5.5-low-concise` on the subscription token by default, and grades it strictly; the trial's diff is the repair alone. Each records whether the reported test now passes (`reported_test_fixed`) and the repair's size. `summary.json` gives per-task cost (cold-equivalent, API-key equivalent), repairs and wall time. The run stops on a 429, an account error, or at `--limit-usd` of known spend as sent, and runs once per prepared directory.
- **Prepared** (`runs/late-fix-20261007-085304`, 7 min, $0, from this change's uncommitted tree on `9f46390`): all 29 misses still fail strictly and have reports. parse's 8 report `test_numbers_without_separators` (`parse.parse('{:,d}', '-7')` returns `None`; 985 bytes). tomli's 17 report `test_line_starts_and_keywords`: keyword construction raises `TypeError` from `__init__` 13 times and from `__new__` 3 times, and once warns (`DeprecationWarning`, an error in that test); 1.3–1.4 KB. - **What it can show.** A lower bound on a late fix: the report gives the failing call, what came back and the test around it, and the culprit is the latest commit. Real symptoms surface downstream with less to go on. Damage stays unmeasured, and so does a second attempt after a failed repair (recorded as a failure).

On Opus 5.5 (`--arm opus-5.5`) the estimate is $8.32. Command in the benchmark plan.

## October 6, 2026: plan item 7, the $0 part: break-even damage and exposure

$0, offline. What an unnoticed miss costs beyond its redo has no measured price, so nothing assumes one; the gate shows what a protection would need it to be, and each change gets an exposure measure. Details: `docs/m6-modelpilot-policy.md`, "Break-even damage instead of an assumed price", and `docs/m6-benchmark-plan.md`, "Exposure and break-even damage".

- **`switch_policy.break_even`.** At each calibrated decision point, for each stronger setting it can reach (weighed as if Jev had named it, on measured pass rates alone), the damage per unnoticed miss above which moving there beats staying: (its expected cost − staying's + the hysteresis) / (its P_ok − staying's). Every decision journals it (`break_even`), `policy_replay` replays and summarizes it, and it changes no decision: damage is priced at 0 (`_decide`'s `damage_usd`, used only by tests, which check that 1% under each figure stays and 1% over moves).
- **Replayed** (`runs/policy-replay-break-even-20261006.json`, `bench-20261006-134508`): Opus 5.5 medium pays at a turn start only above $2.41–2.43 per unnoticed miss, at all 28; at the 8 steps nothing can pay. In hindsight the figure varies by task: Opus 5.5's measured extra cost per miss avoided is $0.77–8.94 (median $2.04; parse $1.51, tomli $2.47, ISMAGS $8.94), which a forecast from the first request can't see (`runs/break-even-20261006.json`).
- **Spec-written tests' break-even** (the October 6 probe's numbers, at low concise's 9.7% miss rate): $0.73 on parse, never on tomli or ISMAGS (no miss flagged); pooled $4.16, $8.13 with the false alarms a host without the reference would see. So item 5's 29-task run (about $3.90) pays only if a miss is worth more than about $4–8.
- **`modelpilot/exposure.py`** (and `line_trace.py`, a standalone tracer run with the bench interpreter): per change, the definitions it touches with their shortest import path and whether that is public API, references to each by name in the repository's source and tests, and which changed lines the task's own suite (the change's test edits dropped) runs inside a test, and how many tests run each changed definition. Over 29 reference fixes and 83 saved fixes (`runs/exposure-20261006-215532`, 6 min): parse's misses touch no public API, yet 87 of 96 existing tests run them; tomli's touch the public `TOMLDecodeError` constructor, run by 5–13 of 14; ISMAGS's 4 public definitions run by 516 of 2,272 tests, with only 2–3% of their changed lines run. A task's failing and passing fixes have the same exposure: it locates a miss's reach, it doesn't predict one. A first run (`runs/exposure-20261006-214844`) counted functions defined inside methods as public API; fixed, superseded, kept.
- **Next** (item 7's measured part): the late-fix harness offline, then its live run (about $2–5 API-key equivalent, estimate; needs the user's go).

## October 6, 2026: plan item 1: Jev only where an answer could change the decision

$0, offline, user's pick of the planned gate over dropping Jev at turn starts. `switch_policy.jev_gate` runs before each advisor call at a turn start or step: Jev's choices and confidences set the candidates (66 answer shapes), and with `recovery.wasted_fraction` 1 every expected cost falls as any P_ok rises, so staying at Jev's estimate 0 against each candidate at 1 bounds every answer. If nothing beats staying by the hysteresis even then, Jev isn't called and the decision is journaled as a stay, `jev_cannot_change`. Always asked on stuck evidence, where a consult is possible, and if `wasted_fraction` drops below 1. Config `jev_gate.enabled` (on); manifests record it; about 8 ms a point. Details: `docs/m6-modelpilot-policy.md`, "Jev only where an answer can matter".

- **Replay first** (`runs/policy-replay-jev-gate-20261006.json`, the seven ModelPilot runs, `--arm modelpilot`): Jev skipped at all 180 recorded decisions (111 turn starts, 69 steps), none moving on the answer Jev gave; the closest comes $0.0116 short of the hysteresis. So the arm, as replayed, makes no Jev call on these runs: no TypeSafe spend, latency or advisor failures, and no prompt sent out.
- **Not vacuous.** At `jev_weight` 0.06 every turn start asks; at 0.065, 0.09, 0.2 and 0.5, 12, 51, 88 and 99 replayed decisions move, every one where the gate asks. A unit test sweeps weights, prompt sizes, warmth, triggers and settings against random answers: every skipped point stays, and some asked points move.
- **An approach dropped on the way.** A first version enumerated point-mass answers and kept a second-order margin (12 × jev_weight² × the recovery cost) for answers between them; at $0.015 that margin exceeded the $0.012 gap at every turn start, so it would never skip. The monotone bound needs no margin.
