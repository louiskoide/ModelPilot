# M4: cascade and shadow-cache planning

Implemented as standalone dry-run planners. No automatic routing, escalation, edits or cache warming is enabled, and these decisions are not yet wired into the proxy or persistent workers.

## Cascade

Read drafts must reproduce an exact span from current host-provided source evidence. Test reports must match a completed host run, its identifier and integer exit code. Changed task revisions reject stale results; changed source hashes reject reads. Candidate confidence cannot authorize acceptance. Edits require escalation because independent patch validation is not implemented; destructive operations are excluded.

Exact-span verification establishes grounding, not relevance or semantic correctness. This is a bounded verifier prototype, not a general judge or a demonstrated cost-saving cascade. Actual fallback execution and end-to-end cascade comparisons remain pending.

## Shadow-cache costs

For one possible switch with probability p, a cold target and an unchanged prefix:

- On-demand expected prefix cost: p × cache write.
- Shadow expected prefix cost: initial write + refresh reads + warmup/refresh output + p × cache read at use.

Identical suffix and useful output costs are excluded from both sides. The model assumes all refreshes hit and the cache survives until use. Prefix growth, expiration misses and invalidation would need additional costs. Explicit expected latency value may justify considering warming, but never enables it.

The offline fixture uses 14,750 prefix tokens, a certain switch and one refresh. With configured five-minute rates, Opus costs $0.0921875 on demand versus $0.1069375 with a shadow; Sonnet costs $0.0553125 versus $0.0641625. Both recommend staying off when latency has no assigned dollar value. These are estimates, not additional API measurements.

## Checks

Eight offline scenarios passed in `runs/m4-dry-run.json`; eleven M4 unit tests cover verification and cost edge cases.

Create a new offline report:

```sh
python3 -m modelpilot.m4 --out runs/m4-plan.json
```

Run the bounded live check from the repository in the Terminal holding your API key:

```sh
python3 -m modelpilot.cascade_check --live
```

This sends two billable Sonnet requests, each limited to 192 output tokens: one source containing a token and one without it. It records draft usage, cost and verification decisions in a new `runs/m4-cascade-*` directory. It stops on failure with no automatic retries. No strong-model fallback or shadow-cache request runs. Without `--live`, it only prints the plan. Both live cases passed; see [results](m4-results.md).
