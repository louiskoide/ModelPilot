## October 19, 2026: Claude Code plugin v0.1, ModelPilot lean mode

$0, no model request. User request: "create the plugin", after the morning's plan to ship the part of ModelPilot that runs inside Claude Code as a plugin. Branch `claude/plugin`, cut from `main` (`d800c1e`) in its own worktree. The main checkout, which `own_sessions --keep` runs from, stays on its branch.

- **New: `plugin/`**, the plugin `modelpilot` 0.1.0. It ships the 4b Sonnet arm's setting (`sonnet-5.5-low-concise`) as far as a plugin can:
  - `settings.json` makes `modelpilot:lean` the default agent.
  - `agents/lean.md` sets `model: claude-sonnet-5-5` and `effort: low` and has an empty body, so Claude Code's system prompt stays (needs client 2.1.281 or later).
  - `hooks/` adds `bench/prompts/concise.md` once at SessionStart. The text is carried in `concise.json` as `additionalContext`. The hook skips it when its input shows another agent or a model other than Sonnet 5.5.
  - `README.md` covers install, what changes, the 4b and tuning numbers, and their limits.
- **New: `.claude-plugin/marketplace.json`**, which makes the repository its own marketplace: `/plugin install modelpilot --marketplace louiskoide/ModelPilot`. This works once the branch is on `main`.
- **Default-on.** The plugin sets the default agent, so it moves an Opus user to Sonnet 5.5. The October 8 quality floor (no worse than the user's own model) holds for Sonnet users only: 4b's Opus floor failed. Default-on was recommended in the planning conversation, with the README telling Opus users what they give up, and the user asked to build it. To make it opt-in instead, delete `plugin/settings.json`; users then run `claude --agent modelpilot:lean`.
- **What the wire check changed: effort.** The plan expected the agent's `effort: low` to set effort. It doesn't: on 2.1.284 and 2.1.303 a plugin agent's effort doesn't reach the main thread, with the `agent` setting or with `--agent`, and every request stays at medium. A plugin can't set effort any other way, since plugin settings honour only `agent` and `subagentStatusLine` and no hook output sets effort. A per-model level saved for Sonnet 5.5 (what `/effort low` writes under `modelSettings`) does apply. So install has one manual step: `/effort low`, then Enter. Without it the plugin gives Sonnet 5.5 medium with the concise text, which was measured on tuning tasks only.
- **How the concise text arrives.** It comes once, in the system message before the first prompt, not appended to the system prompt as in 4b, since a plugin can't append there. The JSON form labels it "SessionStart hook additional context:". Plain stdout labelled it "SessionStart:startup hook success:", so the JSON form was kept.
- **New: `modelpilot/plugin_check.py`** ($0, registered in `commands.py`). It runs a real client with `--plugin-dir`, a fake key and the owned fixture in four cases (`control`, `plugin`, `plugin_saved_low`, `plugin_model_opus`) and reports what reached the model. It also runs `claude plugin validate --strict` on the plugin and on the marketplace.
- **Results:** `runs/plugin-check-2.1.284-20261019.json` and `runs/plugin-check-2.1.303-20261019.json`, in the evidence row. They agree on both clients:
  - the model is set;
  - the system prompt is unchanged;
  - the concise text arrives once, never in the system prompt;
  - effort is medium unless low is saved;
  - `--model` overrides the agent's model;
  - validation passes.
- **Scratch checks, not saved:**
  - Installing from the marketplace at a local path into an isolated config directory gave `modelpilot@modelpilot`, enabled. A fixture session with that installed copy ran Sonnet 5.5 with the concise text once.
  - In `-p` the SessionStart input has `agent_type` but no `model`, so under `--model` the concise text still arrives there.
  - The lean agent is listed in the Agent tool's subagent list, about 58 tokens. Its description says not to delegate to it; nothing enforces that.
