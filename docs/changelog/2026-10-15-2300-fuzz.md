## October 15, 2026 (overnight cloud run): seeded fuzzing of stream parsing and pricing, five bugs fixed

$0, branch `claude/fuzz` (overnight item 7, stacked on `claude/crash-recovery`). New `tests/test_fuzz.py`, standard library only, fixed seeds. The default set takes about 4 s; `FUZZ_ITERATIONS` lengthens it. Details: `docs/m1-results.md`, "Seeded fuzzing of the stream parser and pricing".

- **What it checks:**
  - **Pricing:** `cache_probe.priced_usage` against a reference pricer written in the test from `configs/m0.json` and the documented rules, over usage dicts with missing, extra, null, negative, fractional, boolean and string fields, and nested `server_tool_use`, `iterations` and `cache_creation`.
  - **Streams:** generated Messages SSE through a real `ProxyServer`, cut at random byte boundaries, with LF/CRLF, comments, oversized events and errors. The client must get identical bytes, there must be one row per request, a known cost must equal the reference and never be negative, and the server must keep serving.
- **Found by the default set, fixed in `cache_probe`, each a `FuzzFindingTests` case that fails on the old code:**
  1. Negative token counts were priced, sometimes as a **negative cost**.
  2. Boolean and fractional counts were priced.
  3. A null lifetime split with cache writes priced every write at the 5m rate. That is a smaller wrong total when they were 1h.
  4. A reply whose `iterations` show a fallback's or another model's turn was priced at the asked model's rates.

  Now a count must be a whole number 0 or more, writes without a split are unknown, and fallback iterations are unknown. Recorded runs are unaffected: logged usage keeps only non-negative integer counters.
- **Long run** (seeds 20261015 and 15102026): 1.5 million usage dicts found nothing more. 30,000 streamed replies found a fifth bug, fixed in `proxy.UsageObserver`: a `message_delta` whose usage was a list (`[]`, or pairs) passed `dict.update`, so 125 replies were priced on the placeholder output count. On the fix, 30,000 more replies found nothing (413 s). Logs: `runs/cloud-overnight-fuzz-long*.log`.
- **Tests:** all 911 offline tests pass on Python 3.12 with the pinned 2.1.284 client, no skips (`runs/cloud-overnight-fuzz-regression-py312.log`). The new module, `tests/test_cache_probe.py`, `tests/test_proxy_shapes.py` and `tests/test_dated_rates.py` also pass on Python 3.10.20.
