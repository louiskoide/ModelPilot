## October 15, 2026 (overnight cloud run): an offline end-to-end check of M2–M5 with the governor

$0, branch `claude/e2e-dry-run` (overnight item 3, stacked on `claude/paid-guards`). New `tests/test_e2e_dry_run.py`, test glue only; no production code changed. Details, including what isn't wired: `docs/governor.md`, "Offline end-to-end check (October 15)".

- **What runs:** one scripted session of the pinned 2.1.284 client, all dry-run.
  - **The path:** client → recording relay → governed `ProxyServer` → recording relay → `FixtureServer`. The hooks are in an isolated settings file and `m2_mcp` is the MCP server.
  - **The task turn:** a Read, an `expand_output` call through the MCP server and a Write. A correction is made after the first tool and delivered by the next hook.
  - **Beside the session:** an M3 worker draft through `governed_transport`; M4's span verifier, which accepts that draft and escalates one without a span; and one opt-in `execute_fallback`, admitted and settled.
  - **M5:** an idle boundary crossed on an injected clock (300 s defers, 400 s plans), with effort high→medium coalesced and a compaction that the proxy's context notes show doesn't pay, so it is deferred.
  - **The follow-up:** a resumed turn at the planned effort, after which the plan is acknowledged by observation. Last comes a no-usage reply that halts admission.
- **It holds:**
  - bytes both ways are unchanged through the proxy, statuses included;
  - the proxy's tokens equal the client's cumulative `modelUsage`;
  - governor spend equals the proxy's cost plus the side calls', worked out by hand;
  - no reservation is pending, there is one per proxy row and side call, and `reconcile_log` finds exactly one unknown;
  - the journal is in order and nothing was applied;
  - the plan is acknowledged only after the proxy observed its effort;
  - no stale result lands after the correction (`reject_stale`, a refused observation, no old-revision observation after `corrected`).
  - Passed 5 times in a row and 4 times in parallel; about 4.5 s.
- **Found:** the pinned client sends `HEAD /api/hello` at each invocation's start, even with nonessential traffic off. The proxy answers 501 itself and neither forwards nor logs it, and the client goes on as normal. It isn't billable (`docs/m1-results.md`, "The client's connectivity check").
- **Not wired:** the client never consults M3 or M4 (they share the ledger and budget, called by the coordinator, outside the proxy log). The hooks' idle boundary runs on wall time. In dry-run a halt stops admission but not forwarding.
- **Tests:** all 868 offline tests pass on Python 3.12 with the pinned 2.1.284 client, no skips (`runs/cloud-overnight-e2e-dry-run-regression-py312.log`). The new module also passes on Python 3.10.20 and skips without node or the client.
