## October 16, 2026: the stuck detector sees the agent's Bash test runs; the new signal is observed, not scored

$0, no model request. User request: the fix an outside write-up ("ModelPilot Governor: Why Stuck/Miss Detection Failed", revised October 16) left as the one thing worth doing. Branch `claude/stuck-bash-tests`. Detail: `docs/m6-modelpilot-policy.md`, "Stuck detector v2"; `docs/m2.md`.

- **Before:** M2 read host suites and tool errors only, while agents tested through Bash in 206 of 215 trials. Error hashes were exact, so a failure repeated with a new temporary path or timing never matched.
- **What changed (`heuristic-v2`):**
  - `m2.normalize_error`: directories of absolute paths, line numbers, memory addresses and timings are replaced before hashing. Counts stay.
  - `hooks.agent_test_run`: a Bash call that runs a test runner is observed as `agent_suite`/`agent_failures`, through `delegation`'s recognizer and parser. A passing run comes from PostToolUse's `tool_response`. A failing run comes from PostToolUseFailure's `error`, which is still kept as an error. Never `suite`/`failures`, so host-suite readers don't see them.
  - `stalled_agent_tests` (three non-improving positive counts for one command) is journaled but not scored (`m2.OBSERVED_ONLY`), and the user's stuck notice doesn't list it.
  - New fixtures: a passing and a failing Bash test run recorded from the pinned 2.1.284 against a loopback fake API, fake key, $0 (`tests/fixtures/hooks-2.1.284-bash/`).
- **Why it isn't scored** (`runs/stuck-v2-replay-20261016.py` → `.json`, $0): all 1,039 trials in the 82 bench runs, replayed as the hooks now observe them.
  - The scored rule fires in 1 trial under v1 and v2 alike: the same trial, a strict pass. None of the 146 ModelPilot-arm trials fires.
  - Scored, `stalled_agent_tests` would fire in 6, 5 of them strict passes. In all 6 a test kept failing over three or more runs and the agent then fixed it. Its one miss (compaction arm) had cleared its stall too: its last own run passed, and it missed on the hidden tests.
  - The sqlglot counts never reach 0 because `test_convert` fails at each base (`pytz` missing from the bench venv). Taking it away changes none of the firings (`runs/stuck-v2-base-check-20261016.py` → `.json`, $0). A first reading, that the sqlglot stalls were failures from before the change, was wrong.
  - Refitting the rule to these trials would fit it on the record, so it's left for new evidence and the user's call.
- **A probe built and dropped first:** a Haiku 5.5 test-writer kill test (`miss_testwriter`) was built offline after "lets run that first then". The revised write-up advised against it, and the user chose this fix instead. Nothing was sent or committed. Its offline plan (`runs/miss-testwriter-plan-20261016-155147`, $0.07 expected) and a test log run on the wrong interpreter (`runs/miss-testwriter-regression-20261016-155147.log`) are kept in the ignored `runs/`. That log came from macOS's Python 3.9.6, below the project's 3.10: 16 failures, none in the probe's files.
- **Tests:** all 988 offline tests pass on Python 3.12.14 with the pinned 2.1.284 client first on PATH, no skips (`runs/stuck-v2-regression-py312.log`). New: `tests/test_m2.py` (3: observed apart and never scored; normalization; checked fields) and `tests/test_hooks.py` (4: the recorded runs observed as the agent's; other Bash calls and runs without an outcome; a failure repeated on new paths as one repeated error; a stall alone raises no notice). On the final docs, `tests/test_changelog.py`, `test_hygiene.py` and `test_claude_md.py` pass.
