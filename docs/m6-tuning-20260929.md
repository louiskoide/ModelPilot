of a general winner. ModelPilot and fixed Sonnet 5.5 show no cost or time
difference (see the paired intervals below); router/advisor costs are missing and
repeatability remains to be tested. One effort jump does not validate the switch
policy or governor behavior as a whole.

Preserve this run separately from the earlier incomplete Jev-auth run and the
older run with rejected Opus requests. Next: diagnose the two Haiku task failures,
run the planned variance checks, and use the frozen held-out tasks for final

- **Jev advised every ModelPilot decision.** The 16 decisions were 15
  `turn_start:stay:current_is_cheapest` and one `turn_start:jump:expected_cost_lower`;
  none was `advice_unavailable`. So the stays were agreements that the start
  (Sonnet 5.5 medium) fit the task, not advisor failures.
- **The one jump** was `mi-numeric-range-consistent`: Sonnet 5.5 medium to high on
  the first request, where an effort change rewrites almost nothing, then 4 requests
  at high; passed, $0.0669 cold-equivalent against $0.0756 for fixed Sonnet at
  medium, which also passed. It is one of the two tasks Haiku failed (the other is
  `mi-is-sorted-lt-only`), so Jev picked out a task that was harder for weaker
  settings. One case; it does not show the jump paid.
- **ModelPilot was fixed Sonnet 5.5 on 15 of 16 tasks** (same model and effort),
  which is why they cost the same. Its lead over Jev is the effort confound
  recorded in the benchmark plan: the client sends Jev's `jev-router` placeholder
  high effort, Jev keeps it, and Jev served Sonnet 5.5 on all 16 tasks, while fixed
  Sonnet 5.5 and ModelPilot run at medium. Fixed Sonnet beats Jev by the same
  amount. Jev's router used 19,380 input and 1,968 output tokens for its 16 decisions
  (unpriced).
- **Where ModelPilot's money went** (measured, 16 trials, $0.9765): cache writes
  $0.4395 (45%), output including thinking $0.3605 (37%), cache reads $0.1762 (18%),
  uncached input $0.0004. Tasks took 4–10 main-loop requests. Per-step effort
  changes can only trim thinking inside the output share, and each change adds
  cache writes, so on tasks this short they have little room.
- **Same-setting noise.** On the 13 tasks where ModelPilot stayed at Sonnet 5.5
  medium and fixed Sonnet 5.5 was the cheapest other passing arm, the two arms ran
  the same model and effort, yet per-task cost differed from −27% to +40% (standard
  deviation of the log ratio 0.20, about 14% per trial). The report's eight
  `costlier_tasks` for ModelPilot are this noise. A saving of 5–10% would need many
  more tasks or trials to show.
- **The task set does not separate the arms.** Sonnet 5.5 at medium passed all 16,
  so staying was always right; the switch policy had nothing to win, and pass/fail
  grading can't show whether Opus's fixes were better than Sonnet's. Both are
  follow-up work (harder multi-step tasks; edge-case tests and priced quality).

## Edge-case re-grade (September 29, $0)

`python3 -m modelpilot.regrade runs/bench-20260929-000001` (local output
`runs/regrade-bench-20260929-000001-20260929-173546/results.json`, ignored). It rebuilds each trial's base
checkout, applies the trial's saved `agent.diff`, re-runs the hidden grader against the trial's own bar, runs
the task's frozen edge-case tests (`bench/edge_tests/`, 71 tests over the 16 tuning tasks) and measures the
fix's scope. The edge tests were written from each task's instruction, reference fix and hidden tests before
any arm's fix was opened, and every reference fix passes all of them (see `bench/edge_tests/README.md`).

- **The re-grade reproduces every saved fix's recorded verdict** (77 of 77).
- **Three Haiku fixes were never saved.** In `cachetools-setitem-evict`, `cachetools-ttl-expire` and
  `mi-running-minmax-stable` Haiku ran `git commit` on its fix. The harness took `agent.diff` against `HEAD`,
  so those diffs are empty. Their recorded passes stand (grading uses the working tree), but they can't be
  re-graded. The same `HEAD` comparison fed the test-configuration check, so a committed change to, say,
  `conftest.py` would have gone unflagged. Fixed in `bench.py`: both now compare against the commit the
  harness created, and trials record `agent_moved_head`.

- **No correctness gap between Sonnet 5.5 and Opus 5.5 on these tasks.** Both passed every edge test.
  Opus changed more non-test lines in 10 of 16 tasks (4 equal, 2 fewer) and wrote about 80% more test lines.
  Larger is not better or worse by itself; "non-test" includes documentation the instructions asked for.
  Only a read-through can say whether the extra lines are thoroughness or excess.
- **One incomplete fix passed the hidden grader:** ModelPilot's `parse-decimal-grouping` (Sonnet 5.5 medium)
  rejects a negative number without separators, `parse('{:,d}', '-7')`, although `format(-7, ',d')` gives
  `'-7'`. Fixed Sonnet 5.5 at the same setting got it right, so this is run-to-run variation, not a
  setting difference. Haiku's two edge failures are on tasks it had already failed.
- **Effort may drive test-writing.** The Jev arm served Sonnet 5.5 at high effort and wrote 30.5 test lines
  a task against 21.2 for Sonnet 5.5 at medium. One run; not evidence.
- For priced quality, this set gives the quality term nothing to price: the edge tests found no gap between
  the settings the policy chooses among. Harder tasks, where Sonnet at medium sometimes fails, are still
  needed to calibrate it.
