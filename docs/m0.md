## Experiments and interpretation

- **Effort:** cold → identical warm → changed effort → identical changed effort → return to original. Test system and message breakpoints separately on each model. Compare raw read/write counts, not just latency. A changed-effort write is evidence of invalidation only if its identical warm controls hit.
- **Model:** A cold → A warm → B cold → B warm → A return using the same prefix. An A-return hit distinguishes retained separate entries from eviction.
- **Shadow:** compare zero-token and one-token prewarm, refresh, and a real request with an unchanged cached prefix. Separate cold real-request controls supply the no-shadow comparison. Each arm has a unique leading nonce. Invalid zero-token requests are recorded as errors, never silently converted to one-token requests.
- **TTL:** use independent prefixes for before-expiry and after-expiry trials. A third arm touches at 60% TTL twice, testing refresh across more than one initial TTL. Delays start after responses; no intermediate reads refresh the expiry arm. These are samples around the documented window, not an exact eviction-time estimate. Repeat surprising outcomes with additional delays.

The synthetic prefix must exceed the model's minimum cacheable length. Confirm positive creation tokens on cold controls and substantial read tokens on warm controls; otherwise mark the trial inconclusive. The probe records aggregate usage and isolates breakpoint layers in separate experiments; it cannot attribute mixed usage to arbitrary internal blocks.

Logs contain request hashes, model, effort, usage, cost, request IDs and non-streaming wall time. They omit keys, prompts and generated content. Wall time is full request latency, not TTFT. Failures stop the run with no retry because retries alter cache state and billing. Files are exclusive-created to avoid overwriting prior evidence. This adapter intentionally supports only direct Anthropic requests.

Summarize a live log with:

```sh
python3 -m modelpilot.report runs/m0-live/observations.jsonl > runs/m0-live/report.json
```

Reports leave the gate at `requires_review`. Check the number of recorded steps against `plan.json`; a terminated run is not a complete experiment.

## Economics and gate

Per-request dollars = (uncached input × input rate + 5m writes × 5m rate + 1h writes × 1h rate + cache reads × read rate + output × output rate) / 1,000,000. Write totals are not added again on top of TTL-specific writes.

Prewarming prepays a write and adds refresh/read costs. It can improve first-request latency without saving money. Compare complete lifecycles, including unused shadows, growing prefixes, expiration, and the real request after a warmup. For switching, compare total projected remaining cost of staying with total projected cost of switching; include the target rebuild only once.

Pass M0 only after valid live controls demonstrate model/effort behavior, shadow lifecycle costs and TTL behavior on the intended deployment. Preserve contradictory or inconclusive results. A synthetic API result does not establish Claude Code end-to-end behavior; capture its actual request configuration before M1.

## Findings from documentation, not measurements

The API cache guide describes effort-dependent invalidation, model-specific minimum prefix lengths, five-minute/hour TTLs and paid zero-output prewarming. Claude Code documents an effort-cache exception for certain Fable 5.1 deployments, so a universal effort-switch penalty is unsafe. Sources checked September 21, 2026:

## Remaining build order

M2: stuck detector and reference outputs. Introduce the shared task ledger before persistent workers: task revision, owner, status, cancellation and correction acknowledgments. Preserve full outputs behind durable handles.

M4: cascade with acceptance criteria by operation type; shadow maintenance only when M0 economics support it.

M5: coalesce changes at measured expiry, justified switches and explicit user/goal-boundary compaction. Add budgets and offline threshold learning with held-out evaluation.

M6: paired evaluation on fixed tasks and repository revisions against fixed model/effort settings and the specified jev-router revision.
